# Role Detail Pages — Proposal

# Objective

Introduce dedicated role ecosystem pages that allow users to explore active preparation communities for specific roles.

This phase builds on Discovery V2 Foundation and strengthens the platform’s role-centric identity.

The goal is NOT to create a social network.

The goal is to make users feel:
“People like me are seriously preparing here.”

---

# Product Vision

Each role should feel like:

* active
* alive
* preparation-focused
* structured
* accountability-oriented

Role pages should create belonging and ecosystem identity without introducing social-media behavior.

---

# Scope

## Included

### Dedicated Role Pages

Examples:

* /roles/nodejs-developer
* /roles/data-analyst
* /roles/product-manager

### Role Overview

Each page includes:

* role title
* total aspirants
* active today
* role summary
* top preparation focus areas
* ecosystem preparation insights

### Active Preparation Signals

Anonymous ecosystem indicators:

* recent preparation activity
* check-in momentum
* interview preparation indicators
* active learner counts

### Popular Skills / Focus Areas

Examples:

* Express.js
* MongoDB
* APIs
* SQL
* React
* Power BI

### Common Daily Goals

Examples:

* Solve DSA questions
* Apply to companies
* Revise backend concepts
* Practice interviews

### Preparation Journey Visualization

Structured preparation stages such as:

* Learning
* Building
* Applying
* Interviewing

This is informational only in this phase.

### Matching Entry CTA

Primary CTA:
“Find Preparation Partner”

This should connect naturally to the existing matching system.

---

# Explicitly NOT Included

* public posting systems
* comments
* likes/reactions
* open social feeds
* influencer behavior
* user-generated public content
* public profiles
* group communities
* group chat
* AI coaching systems

---

# Product Rules

Role pages MUST remain:

* structured
* anonymous
* preparation-focused
* ecosystem-oriented

Role pages must NOT become:

* social media
* public forums
* LinkedIn-style spaces

---

# UX Goals

Users should feel:

* they are not preparing alone
* others are actively progressing
* this role has serious aspirants
* the platform has ecosystem depth

The UI should communicate:
“serious preparation environment.”

---

# Technical Requirements

* preserve existing architecture
* preserve existing matching logic
* preserve existing APIs where possible
* build modular reusable role components
* support future ecosystem expansion

---

# Future Compatibility

Architecture should support future additions:

* peer interview mode
* role analytics
* preparation stage matching
* ecosystem insights
* role-specific onboarding improvements

without requiring major rewrites.
